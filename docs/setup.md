# 公開までの手順

KESEN LARUS スタッフカレンダーを実際に使える状態にするまでの手順です。
プログラミングの知識は不要ですが、**30〜40分**ほどかかります。

料金は**月額0円**です（Supabase・Vercel の無料枠に収まります）。

---

## 0. 用意するもの

次の3つのアカウントを作ります。いずれも無料で、GitHub アカウントがあれば
残り2つは「GitHubで続ける」を押すだけで作れます。

| サービス | 役割 | 登録先 |
|---------|------|--------|
| GitHub | プログラムの置き場所 | https://github.com |
| Supabase | データの保存先 | https://supabase.com |
| Vercel | アプリの公開先 | https://vercel.com |

あわせて、**スタッフ共通の合言葉**を決めておいてください。
6文字以上で、社外の人に推測されにくいものにします（例: 店名と数字の組み合わせなど）。

---

## 1. データの保存先（Supabase）を用意する

### 1-1. プロジェクトを作る

1. https://supabase.com にログインし、**New project** を押す
2. 次のとおり入力する
   - **Name**: `kesen-larus-calendar`（何でも構いません）
   - **Database Password**: 自動生成のままでOK。**この画面を閉じる前にどこかに控えておく**
   - **Region**: `Northeast Asia (Tokyo)` を選ぶ（日本から一番速い）
3. **Create new project** を押す。準備に1〜2分かかります

### 1-2. テーブルを作る

1. 左のメニューから **SQL Editor** を開く
2. このリポジトリの `supabase/schema.sql` の中身を**すべてコピー**して貼り付ける
3. **Run** を押す

「Success. No rows returned」と出れば成功です。
左メニューの **Table Editor** を開くと `staff` `categories` `events` の3つの表ができていて、
`staff` にはスタッフ5名、`categories` には分類6件が入っています。

> このSQLは何度実行しても同じ結果になります。間違えて2回実行しても問題ありません。

### 1-3. 接続用の情報を控える

1. 左メニューの一番下 **Project Settings** → **API** を開く
2. 次の2つをメモ帳などに控える

| 項目 | 画面上の名前 | 例 |
|------|------------|-----|
| プロジェクトのURL | **Project URL** | `https://abcdefgh.supabase.co` |
| 秘密のキー | **service_role**（`Project API keys` の中） | `eyJhbGci...`（とても長い文字列） |

> **service_role キーは絶対に他人に見せないでください。** これがあればデータを自由に
> 読み書きできます。メールやチャットに貼らず、Vercel の設定画面にだけ入力します。
> （`anon` の方のキーはこのアプリでは使いません）

---

## 2. 合言葉を用意する

合言葉はそのまま保存せず、**ハッシュ**という読めない形に変換して設定します。
万一設定画面を覗かれても、合言葉そのものは分かりません。

### パソコンにプログラムを動かす環境がある場合

このリポジトリを手元に取得して、次を実行します。

```bash
npm install
npm run passcode -- 実際の合言葉
```

`APP_PASSCODE_HASH=scrypt$...` という行が出るので、これを控えます。

### 環境がない場合

ハッシュ化は省略できます。手順3で `APP_PASSCODE_HASH` の代わりに
`APP_PASSCODE` に合言葉をそのまま設定してください。
（Vercel の環境変数は暗号化して保管されるため、これでも実用上の問題はありません。
　余裕ができたらハッシュに切り替えることをおすすめします）

---

## 3. 公開する（Vercel）

### 3-1. プロジェクトを作る

1. https://vercel.com にログインし、**Add New** → **Project** を押す
2. このリポジトリ（`Calendar`）を選んで **Import**
3. **Framework Preset** が `Next.js` になっていることを確認する（自動で選ばれます）

### 3-2. 環境変数を入れる

**Deploy を押す前に**、`Environment Variables` の欄に次の4つを入れます。

| 名前 | 値 |
|------|-----|
| `APP_PASSCODE_HASH` | 手順2で作った `scrypt$...`（ハッシュ化しない場合は代わりに `APP_PASSCODE` に合言葉そのもの） |
| `SESSION_SECRET` | ログイン状態の署名に使う長い文字列。下記参照 |
| `SUPABASE_URL` | 手順1-3の **Project URL** |
| `SUPABASE_SERVICE_ROLE_KEY` | 手順1-3の **service_role** キー |

`SESSION_SECRET` は、次のどちらかで作った32文字以上のランダムな文字列を使います。

- パソコンのターミナルで `openssl rand -base64 32` を実行する
- https://generate-secret.vercel.app/32 を開いて表示された文字列を使う

### 3-3. 公開する

**Deploy** を押します。2〜3分で完了し、`https://◯◯◯.vercel.app` というURLが表示されます。
これがスタッフに配るURLです。

---

## 4. 動作を確かめる

1. 表示されたURLを開く
2. 合言葉を入力する → 名前を選ぶ → カレンダーが出る
3. 右下の **＋** から予定を1件登録する
4. **別の端末（スマホなど）** で同じURLを開き、その予定が見えることを確かめる

ここまで確認できれば完成です。

---

## 5. スタッフに配る

スタッフには次の3点を伝えます。

1. **URL**（`https://◯◯◯.vercel.app`）
2. **合言葉**
3. **最初に自分の名前を選ぶこと**

スマホでは、ブラウザの共有メニューから **「ホーム画面に追加」** しておくと
アプリのように開けます（iPhone は Safari、Android は Chrome から）。

---

## 6. ふだんの運用

### スタッフを増やす・減らす

カレンダー画面の右上の歯車 → **設定** から、スタッフの追加・改名・色の変更ができます。
退職した人は「在籍」を切ります。**削除はしません。** 過去の予定に名前を残すためです。

### 分類を増やす

同じ設定画面から分類を追加できます。使われている分類は削除できないので、
使わなくなったものは「表示」を切ってください。

### 合言葉を変える

Vercel の **Settings** → **Environment Variables** で `APP_PASSCODE_HASH`
（または `APP_PASSCODE`）を書き換え、**Redeploy** します。
変更すると**全員がログインし直し**になります。新しい合言葉を先に共有してください。

### データのバックアップ

Supabase の **Database** → **Backups** から取得できます。
無料プランでも直近数日分が自動で保存されます。

## 7. 困ったとき

| 症状 | 確認すること |
|------|------------|
| 「合言葉がまだ設定されていません」と出る | `APP_PASSCODE_HASH`（または `APP_PASSCODE`）が設定されているか。設定後に Redeploy したか |
| 合言葉が合っているのに入れない | ハッシュを作ったときの合言葉と、入力している合言葉が一致しているか |
| 「入力を続けて間違えたため…」と出る | 5回続けて間違えたための一時的なロックです。15分待つと解除されます |
| 予定が表示されない・保存できない | `SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` が正しいか。手順1-2のSQLを実行したか |
| 他の人の変更がすぐ反映されない | 30秒ごと、およびタブに戻ったときに自動で読み直します。すぐ見たい場合は画面を再読み込みしてください |

## 付録: 手元で動かす（開発用）

プログラムを変更して試したい場合の手順です。

```bash
npm install
cp .env.example .env.local
```

`.env.local` を開き、`APP_PASSCODE` と `SESSION_SECRET` だけを埋めます
（`SUPABASE_` の2つは空のままで構いません）。

```bash
npm run dev
```

http://localhost:3000 を開きます。

Supabase の設定が空のときは、データは `.data/db.json` というファイルに保存されます。
手元で試すためのもので、本番では使われません。消せば初期状態に戻ります。

その他のコマンド:

```bash
npm test        # 日時計算などの自動テスト
npm run build   # 本番と同じ形に組み立てて、壊れていないか確かめる
```
