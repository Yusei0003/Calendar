## 1. 認証・利用者（決定）

- **入り方: スタッフ全員で共通の合言葉（パスコード）1つ**
- 人数規模: 5人（下記）
- 端末: PC・スマホ両方

### 合言葉方式の補強

合言葉だけだと「誰が登録・変更したか」が残らず、予定の持ち主も指定できません。**2段構え**にします。

1. **合言葉を入力** → アプリに入れる（アクセス制御）
2. **「あなたは誰？」でスタッフ名を選ぶ** → 端末に記憶（名乗り）

名乗りはパスワードではないため、なりすまし防止にはなりません。
「自分の予定をすぐ出す」「更新履歴に名前を残す」ための仕組みです。
後から Google ログインへ移行できるよう、スタッフ情報は独立したテーブルで持ちます。

### セキュリティ上の設計判断

- 合言葉は**ブラウザ側で照合しない**。Next.js のサーバー側で照合し、成功したら
  httpOnly Cookie（署名付き・有効期限1年）を発行する。
- データベースへのアクセスは**すべてサーバー経由**。ブラウザに DB のキーを置かない。
- 合言葉はハッシュ化して環境変数で管理。変更は環境変数の差し替えのみ。
- 5回連続失敗で同一IPを15分ロック（総当たり対策）。
- ★ 合言葉の文字列は運用開始時に決定。変更したら全員が再入力になる。

## 2. データモデル

### 2.1 スタッフ（staff）— 初期メンバー確定

| 表示名 | 備考 |
|--------|------|
| 脇坂健吾 | |
| 和田悠晟 | |
| 小山裕介 | |
| 熊谷大輔 | |
| 今野和倫 | |

- 部署・店舗の区分は**持たない**（必要になったら後から追加可能な設計にする）
- 各スタッフに**アクセントカラー**を1色割り当て（管理画面で変更可）
- 並び順・在籍フラグを持つ。退職時は非表示にするが過去の予定は残す
- 管理画面から**追加・編集・並べ替えが可能**

### 2.2 予定（events）

用途が「スタッフの予定共有」と「イベント・営業スケジュール」の2つなので、
1つのテーブルに **種別** を持たせて区別します。

| 項目 | 必須 | 内容 |
|------|------|------|
| 種別 | ● | `スタッフ予定` / `全体予定`（イベント・営業） |
| 担当スタッフ | 種別による | スタッフ予定は必須、全体予定は任意 |
| タイトル | ● | 例:「◯◯様 打合せ」 |
| 開始 / 終了 | ● | 日時。タイムゾーンは日本時間固定（DB は UTC 保存） |
| 終日フラグ | ● | ONなら時刻を持たない |
| 分類 | ● | 2.3 の分類マスタから選ぶ |
| 場所 | | 自由入力 |
| メモ | | 自由入力（複数行） |
| 登録者 / 更新者 | ● | 名乗ったスタッフ名を自動記録 |

削除は**論理削除**（実際には消さずに隠す）。誤操作から復旧できる。

### 2.3 分類（categories）— マスタ管理

固定の選択肢ではなく**マスタテーブル**として持ち、管理画面から随時追加・編集・並べ替えできる。

初期値:

| 分類 | 色 |
|------|-----|
| 休み | 実装時に配色決定 |
| 外出 | 〃 |
| 来客・打合せ | 〃 |
| 会議 | 〃 |
| イベント・催事 | 〃 |
| その他 | 〃 |

- 使用中の分類は削除不可（代わりに「非表示」にする）。既存の予定が分類を失わないため。
- 各分類にアイコンを1つ割り当て、色に頼らず区別できるようにする。

### 2.4 色分けの主軸

- **主: スタッフごとの色**（誰の予定かが一目で分かることを優先）
- **従: 分類**（アイコン＋左端の細い帯で表現）
- 全体予定はスタッフ色を持たないため、分類色を主として表示する

### 2.5 繰り返し予定（v1 では扱わない）

**決定: v1 は単発の予定のみ。繰り返しの設定UIは載せない。**

ただし**データ構造は最初から繰り返しに対応した形で作る**ため、後から機能を足しても
データの作り直しは発生しない。具体的には events テーブルに次のカラムを最初から持たせる。

| カラム | v1 での値 | 将来の用途 |
|--------|----------|-----------|
| 繰り返し規則 | 空 | 毎日 / 毎週（曜日指定） / 毎月（日付指定） |
| 繰り返し終了日 | 空 | 繰り返しの終了条件 |
| 親予定ID | 空 | 「この回だけ変更」した予定が元をたどるため |

v1 での代替手段: **予定の複製**（「同じ内容で別の日に」ボタン）。
毎週の定例は、数回分をまとめて複製して登録する運用とする。

## 3. 画面・機能

### 3.1 画面一覧

| 画面 | 内容 |
|------|------|
| 入場 | 合言葉入力 → スタッフ名を選ぶ |
| 月表示 | 1か月の俯瞰。PCの既定表示 |
| 週表示 | 縦が時間・横が日付のタイムライン |
| 日表示 | 1日をスタッフ別の列で表示（誰が今日何をしているか） |
| リスト | 今日以降の予定を時系列で。**スマホの既定表示** |
| 予定の追加・編集 | 下からせり出すパネル（スマホ）／右サイドパネル（PC） |
| 管理 | スタッフ（名前・色・並び順）と分類マスタの編集 |

### 3.2 共通の操作

- 上部にスタッフを並べ、**タップで絞り込み**（「脇坂さんの予定だけ」）
- 分類でも絞り込み
- 「今日」に戻るボタン、左右スワイプ／矢印キーで前後の月・週へ
- 空いている枠をタップ → その日時で新規作成が開く
- 予定の複製（「同じ内容で別の日に」）

### 3.2.1 ドラッグ操作（v1 に含める）

| 表示 | できること |
|------|-----------|
| 月表示 | 予定を掴んで別の日へ移動（所要時間は保ったまま日付だけ変わる） |
| 週表示 | 予定を掴んで別の日時へ移動／上下の端を引っ張って開始・終了時刻を変更 |
| 日表示 | 上下の端を引っ張って時刻を変更（スタッフ列をまたぐ移動で担当者変更） |

誤操作対策（ドラッグを入れる以上、必須）:

- **取り消し（Undo）**: 移動後に「元に戻す」が数秒間表示される。Ctrl+Z / Cmd+Z にも対応
- **スマホでは長押ししてから**ドラッグ開始（画面スクロールとの誤認を防ぐ）
- ドラッグ中は移動先の日時を常時表示し、離す前に確認できるようにする
- 時刻は15分単位に吸着させる
- 過去の日付へ落とした場合は確認を挟む

### 3.3 やらないこと（v1 のスコープ外）

- 予定の承認フロー、シフトの自動組み
- Google カレンダーとの**書き込み・双方向同期**（3.4 参照。読み取りのみは対応）
- 添付ファイル、コメント・チャット機能
- **通知（メール・LINE・プッシュ）— v1 では実装しない**。アプリを開いた時に
  「今日の予定」が最初に出る作りでカバーする。必要になった時点でメール朝配信を追加する
- 繰り返し予定の設定UI（2.5 参照）

### 3.4 Google カレンダー連携（読み取り専用・決定）

各スタッフ本人の Google カレンダーの予定を、このアプリに読み取り専用で取り込んで表示する。
「クラブの予定を配る」方向（本アプリ→他サービス）ではなく、その逆（本人のGoogleカレンダー→本アプリ）。

**方式**: Google カレンダーの「秘密のアドレス（iCal形式）」を、本人が設定画面に登録する。
OAuth・Google Cloud の設定は不要。

| 項目 | 内容 |
|------|------|
| 対象 | 本人の分のみ。他人の URL は本人以外、閲覧も変更もできない（サーバー側で保証） |
| 取得方法 | サーバーが定期的に ICS を取得・解析し、他の予定と合わせて配信する |
| アクセス先の制限 | `calendar.google.com` 以外へは接続しない（サーバーに任意の URL を取りに行かせる攻撃＝SSRFを防ぐため） |
| 反映のタイムラグ | 取得結果を15分キャッシュする。Google側の更新頻度自体も数時間おき |
| 編集 | **不可**。カレンダー上ではっきり区別して表示し（点線の帯＋専用アイコン）、
クリックすると読み取り専用の詳細だけを表示する。ドラッグ・削除の対象にもならない |
| 分類・絞り込み | 分類を持たない予約IDを使うため、分類での絞り込みをかけると自動的に隠れる。
スタッフでの絞り込みでは、その人を選ぶと一緒に表示される |
| 退職時 | 在籍フラグを切ると、本人の連携が残っていても表示されなくなる |

繰り返し予定（RRULE）・一部の回だけ変更（RECURRENCE-ID）・除外日（EXDATE）にも対応する。

## 4. デザイン方向性（決定: C案）

**端末の設定に合わせてライト／ダークを自動切替**。アプリ内で手動切替も可能にする。

- ダーク: 濃紺〜黒の背景に、スタッフごとの鮮やかなアクセントカラー。予定が光って見える
- ライト: 白基調・余白広め。日中の事務所で見やすい
- 両モードで同じ配色設計（同じ色相を明度違いで持つ）ため、印象は一貫する

共通で担保するもの:

- スマホは片手で操作できる（主要ボタンを下部に配置）
- 文字と背景のコントラスト比 4.5:1 以上（**両モードで**検証する）
- 色だけに頼らず、分類はアイコンでも区別（色覚多様性への配慮）
- 日本語フォントで数字・曜日が詰まって見えないよう調整

## 5. 技術構成・公開方法（決定）

| 領域 | 採用 | 理由 |
|------|------|------|
| フレームワーク | Next.js (App Router) + TypeScript | UI の自由度が高く、サーバー処理も同居できる |
| データベース | Supabase (PostgreSQL) | 無料枠で開始でき、後から認証強化・リアルタイム同期に拡張できる |
| スタイル | Tailwind CSS | 細かいデザイン調整がしやすい。ライト／ダーク両対応が容易 |
| 公開先 | Vercel | Next.js との相性。無料枠・独自ドメイン可 |
| 日時処理 | date-fns（tz: Asia/Tokyo 固定） | 軽量。UTC 保存 → 表示時に日本時間へ |

### 更新の反映

v1 は**画面を開いた時・タブに戻った時・30秒ごと**に最新を取得する方式（5人ならこれで十分）。
リアルタイム同期は v2 で Supabase Realtime を使って追加可能。

### 公開URL（決定）

**Vercel の無料URL（`◯◯.vercel.app`）で開始する。** 独自ドメインは使わない。
後から独自ドメインを当てることは可能で、その際もアプリの作り直しは発生しない。

### 運用コスト

**月額 0円**。Supabase・Vercel とも無料枠の範囲に収まる見込み（5人・月数百件の予定）。

## 6. 実装の順番

| 段階 | 内容 | 完了時に確認できること |
|------|------|----------------------|
| 1 | 土台構築・DB設計・合言葉ログイン | 合言葉で入って名前を選べる |
| 2 | 予定の登録・編集・削除 + 月表示 | 実データを入れて月カレンダーで見られる |
| 3 | 週 / 日 / リスト表示、絞り込み | スマホ・PC 両方で実用的に使える |
| 4 | ドラッグ操作 + 取り消し | PC で予定を掴んで動かせる |
| 5 | 管理画面（スタッフ・分類マスタ） | 自分たちで分類を増やせる |
| 6 | デザイン仕上げ・ライト/ダーク調整 | 「かっこいい」状態になる |
| 7 | Vercel へ公開・スタッフへ配布 | 本番運用開始 |

各段階の終わりに実際に触れる状態で共有し、方向を確認しながら進めます。
